# Distributed-Broadcast-Simulation
Design and Experimental Evaluation of Diffuse-v3 Broadcasting on Synthetic and Real-World Network Topologies Using OMNeT++


## Team

| Role | Student | Responsible for | Presents |
|---|---|---|---|
| A, Algorithms | Student A | Diffuse-v3 specification, `Node3.cc` fixes and measurements, hand traces | Opening, state of the art, algorithm walk-through, conclusions |
| B, Simulation | Student B | Validation networks V1–V7, INI campaigns, batch runs, failure model, result export | OMNeT++ design, live demo |
| C, Evaluation | Student C | Topology generator, SNDlib topologies, analysis script, figures, report assembly | Problem and hypotheses, results |

Every member reviews another member's pull requests, and everyone must be able to explain the algorithm and every figure.

## Problem statement
In a distributed system, information must be disseminated from an initiating process to other processes through message-passing communication.
The challenge is that different network structures and communication conditions can substantially affect the behavior of a broadcasting protocol.
A protocol that behaves efficiently on a small tree may generate different communication overhead on a densely connected network.
Our project will investigate this behavior systematically.

So our question here is **How do network topology, network size, communication delay, and node failures affect the correctness and performance of the Diffuse-v3 distributed broadcasting algorithm?**

## Hypotheses to test
- **H1** For a fixed number of nodes, changing network connectivity can change the number of messages generated by Diffuse-v3.
- **H2** Increasing communication delay increases broadcast dissemination time when other conditions remain unchanged.
- **H3** The position of the initiator influences dissemination time, particularly in networks with long paths.
- **H4** Node failures and message loss can reduce the proportion of reachable nodes receiving the broadcast.
- **H5** The benefits of using information contained in Diffuse-v3 messages may involve a trade-off between transmission count and message size.

## Project layout

Files that exist today, and the folders each step will add (marked *planned*):

```text
Distributed-Broadcast-Simulation/

│   ├── Node3.ned             # Node3 module type (gates, parameters)
│   └── DiffuseMessage.msg    # broadcast message carrying the control set Z
├── simulations/
│   ├── omnetpp.ini           # run configurations
│   ├── Network3.ned          # 9-node lab network, the reference run
│   ├── validation/           # test networks V1–V7 (Single, Line6, Tree7, Ring4, Cyclic6, Gaps)
│   ├── synthetic/            # planned: line, ring, tree, grid, complete, random
│   └── real/                 # planned: Abilene, Geant, Germany50 (SNDlib)
├── data/topologies/          # planned: source graphs and manifest
├── scripts/                  # summary.sh, run_validation.sh; planned: generate, run, export, analyze
├── tests/                    # hand traces and validation results
├── results/                  # planned: processed CSV files and figures
├── docs/                     # specification, methodology, AI usage log
├── report/                   # planned: 3-5 page report
└── presentation/             # planned: slides and demo material
```

## Build and run

Requires OMNeT++ 6.3.0 or later (also tested with 6.4.0). Activate it in every new terminal first:

```bash
source ~/omnetpp-6.3.0/setenv
```

Build (the first command (make makefiles) generates `src/Makefile`, needed once per clone):

from the root directory of the project 

```bash
make makefiles 
make
```

Run the reference lab network in batch mode:

```bash
cd simulations
../src/diffuse -u Cmdenv -n ../src:. -c RunDiffuse3
```

Use `-u Qtenv` instead of `-u Cmdenv` for the graphical run.
Expected for `RunDiffuse3` (9 nodes, 9 links, 100 ms per link): 10 messages, simulation ends at t = 0.4 s.
