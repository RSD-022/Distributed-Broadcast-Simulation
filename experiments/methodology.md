# Diffuse-v3 experiment methodology

## 1. Setup

The team ran batch `campaign-02` with **OMNeT++ 6.4.0** in **Cmdenv** and recorded `afd1280` as the code revision. Each run starts one broadcast with one initiator.

To reproduce a campaign, build the recorded revision in an OMNeT++ 6.4.0 environment. From the repository root, replace `CONFIG` with the configuration name in the INI file and `BATCH` with the batch name. Use the same name for both commands and a fresh batch name when repeating an existing run.

```bash
scripts/run_campaign.sh CONFIG BATCH
scripts/export_results.sh CONFIG BATCH
```

The exporter reads the batch's `.sca` files and writes `results/processed/CONFIG.csv` in CSV-S format. Each scalar row identifies its run, node, metric and value. Sweep columns identify the parameter values used in that run.

## 2. Campaigns

The three real networks are Abilene, Geant and Germany50. The six synthetic families are line, ring, tree, grid, complete and random. C1 through C3 run without crashes or losses. Each deterministic parameter combination runs once.

| Campaign | Hypothesis | Varies | Fixed | Runs |
| --- | --- | --- | --- | ---: |
| `C1_Size` | H1, H5 | 6 synthetic families × 4 sizes (10, 20, 50, 100 nodes) | 1 ms delay, initiator 0 | 24 |
| `C2_Delay` | H2 | 3 real networks × constant delay `d` = 1, 5, 10 ms | Initiator 0 | 9 |
| `C2_RandomDelay` | H2 | 3 real networks with `uniform(1ms,10ms)` channel delays | Initiator 0, 10 repetitions per network | 30 |
| `C3_Initiator_*` | H3 | Every node gets one turn as initiator in each real network | 1 ms delay | 12 + 22 + 50 = 84 |
| `C4_Crash` | H4 | Crash probability `p` = 0, 0.1, 0.2, 0.3 on Geant | 1 ms delay, initiator 0, no loss, 20 repetitions per level | 80 |
| `C4_Loss` | H4 | Loss probability `q` = 0, 0.05, 0.1, 0.2 on Geant | 1 ms delay, initiator 0, no crashes, 20 repetitions per level | 80 |
| **Total** | | | | **307** |

The table uses the roadmap label `C2_Delay`. 

The roadmap uses the H1–H5 labels from the [project README](../README.md). The hypothesis statements below reproduce its wording.

- **H1** For a fixed number of nodes, changing network connectivity can change the number of messages generated by Diffuse-v3.
- **H2** Increasing communication delay increases broadcast dissemination time when other conditions remain unchanged.
- **H3** The position of the initiator influences dissemination time, particularly in networks with long paths.
- **H4** Node failures and message loss can reduce the proportion of reachable nodes receiving the broadcast.
- **H5** The benefits of using information contained in Diffuse-v3 messages may involve a trade-off between transmission count and message size.

## 3. Link model

`Link` extends OMNeT++ `ned.DelayChannel`. It models propagation delay only, with no data rate or queueing. The constant delay is 1 ms unless the campaign changes it. In `C2_RandomDelay`, each directed channel draws one delay uniformly between 1 and 10 ms during initialization and keeps it for the entire run. The two directions of a link can therefore have different delays.

## 4. Failure models

- **Crash.** At simulated time zero, each non-initiator independently crashes with probability `p`. A crashed node counts and discards messages that arrive. It never becomes informed or forwards a message. The initiator stays alive.
- **Loss.** Each attempted transmission is independently dropped with probability `q`. A dropped copy increments the sender's `sent` and `lost` counters. It makes no contribution to `received`. The model has no retries.

## 5. Randomness and seeds

With `seed-set = ${repetition}`, repetition `r` uses seed set `r` at every `p` level in the crash sweep and at every `q` level in the loss sweep. This is a **common random numbers** design. Sharing a seed pairs the repetitions across levels and can reduce noise in the comparison when the paired outcomes are positively correlated. In the loss sweep, changes in forwarding can change which transmission uses a particular random draw.

`C1_Size`, `C2_Delay` and the `C3_Initiator_*` configurations are deterministic, so one run per combination is sufficient. C1 loads fixed graph instances, including those from the random family.

## 6. Stopping rule

The broadcast ends when the event queue is empty. `sim-time-limit = 100s` serves as a safety stop. In the team's `campaign-02` results, no broadcast reached the safety limit. The largest measured dissemination time `T` was 99 ms on `Line100`.

## 7. Metrics

Group CSV-S rows by run and node before aggregating. Let `n` be the original number of nodes. Every sum below is over the nodes in the same run.

| Metric | Calculation |
| --- | --- |
| Messages attempted (`M`) | Sum of `sent`. |
| Messages received | Sum of `received`. |
| Lost copies | Sum of `lost`. |
| Duplicate arrivals | Sum of `duplicates`. |
| Dissemination time (`T`) | Maximum `firstReceptionTime` over informed nodes, ignoring `nan`. The scalar is in seconds. Multiply by 1,000 to report milliseconds. |
| `coverageAll` | Sum of `informed` divided by `n`. |
| `coverageAlive` | Number of informed survivors divided by the number of survivors. A survivor has `crashed = 0`. |
| `coverageReachable` | Number of informed survivors in the initiator's reachable component divided by the size of that component. Remove crashed nodes and their incident edges from the graph, then traverse the remaining graph from the initiator. |
| Control data | Sum of `zEntriesSent`. Estimate bytes as four times this sum, **assuming four bytes per node ID**. This estimates the size of the Z entries across all attempted copies, including lost copies. |

For an incomplete run, `T` is the last first-reception time among the nodes that became informed. Set the full-network completion time to missing whenever `coverageAll < 1`.

## 8. Checks done

We reported the following checks for `campaign-02`.

- In all 307 runs, `sum(sent) = sum(received) + sum(lost)`.
- In the reliable runs, all `n` nodes became informed and `duplicates = M − (n − 1)`. The message count satisfied `n − 1 ≤ M ≤ 2m - (n-1)`, where `m` is the number of undirected edges. The lower bound accounts for the `n − 1` non-initiators that need a first delivery. The upper bound allows one send per edge direction.
- In the reliable runs with a constant delay `d`, `T = ecc × d`, where `ecc` is the initiator's maximum shortest-path distance to any node, in hops. The random-delay runs have no single common `d`.
- `campaign-02` reproduced the measured values from `campaign-01` for the same run settings. Filenames, run IDs and timestamps identify each execution.
